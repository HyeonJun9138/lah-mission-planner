LAH/회전익기 안전 경로계획 강화학습 설계서 v3
(Fixed Global Reference Path + Terrain/Route Risk Analysis + HTML/Python Simulation)

이 문서의 목적
- 이 문서는 실제 GeoTIFF DEM을 사용해 LAH 같은 회전익기의 3차원 안전 경로계획 강화학습 시스템을 설계하기 위한 상세 텍스트 설계서다.
- 이번 버전은 사용자의 추가 조건을 반영해 "전역경로(global path)는 AI가 새로 만드는 것이 아니라, 운용자가 사전에 입력한 거의 직선 위주의 reference path(ref path)"라고 가정한다.
- 따라서 RL은 전역경로 생성기가 아니라, "고정된 ref path를 기본으로 따라가되, 지형/위험 때문에 필요할 때만 국소적으로 벗어나고 다시 복귀하는 로컬 3D 경로계획기(local planner)"로 설계한다.
- 지형 분석, 경로 주변 위험 분석, corridor 기반 우회, holding, HTML 시뮬레이터, stable-baselines3 학습 구조를 모두 포함한다.
- 단, 적 위치 추정 / 적 LOS / 피격 회피 / 전술적 군사 최적화는 포함하지 않는다. 위험은 비적대적 항공안전 위험으로만 정의한다.

================================================================================
0. 이번 버전의 핵심 변경점
================================================================================

기존 혼동 지점
- 전역경로를 RL이 직접 만들어야 하는지, 아니면 외부에서 이미 정해져 있는지 모호했다.

이번 버전의 확정 가정
- 전역경로 = 운용자가 사전에 입력한 ref path
- ref path = 거의 직선 위주의 piecewise-linear polyline
- RL의 역할 = ref path를 완전히 버리는 것이 아니라, 그 경로를 기준으로 일정 corridor 안에서 더 안전한 3D 경로를 찾는 것
- 즉, RL은 "route follower + local deviation planner + safe recovery planner" 역할을 한다.

이 가정의 장점
- 학습 난이도가 크게 낮아진다.
- 실제 운용과 유사하다.
- 보상 설계가 명확해진다.
- "경로 유지"와 "필요 시 우회"를 동시에 설계하기 쉬워진다.
- 완전 자유형 3D 탐색보다 훨씬 안정적으로 학습된다.

- 제한구역/민감구역/인구밀집구역 상공 통과
- 외부 장애물(송전선, 타워, 건물) 근접
- 기상/시정/강풍 등 확장 위험
- 비상착륙 부적합 지역 통과
- 과도한 기동과 불안정한 속도/고도 변화

================================================================================
5. ref path 설계 (이번 버전의 핵심)
================================================================================

5.1 ref path 정의
- ref path는 운용자가 사전에 입력한 polyline이다.
- 거의 직선 위주이므로 waypoint 수가 많지 않아도 된다.
- 예:
  [
    [x0, y0, z_ref0],
    [x1, y1, z_ref1],
    [x2, y2, z_ref2],
    ...
  ]

5.2 ref path의 역할
- 절대 따라야 하는 강제 레일은 아니다.
- "기본 진행 방향과 임무 기준축" 역할을 한다.
- RL은 이 경로를 중심으로 일정 corridor 범위 안에서 안전한 로컬 우회를 할 수 있어야 한다.
- 위험이 줄어들면 다시 ref path 쪽으로 복귀하게 만든다.

5.3 ref path 전처리
- 입력 polyline을 일정 간격(예: 50 m 또는 100 m)으로 resample
- 각 샘플 포인트마다 tangent(진행 방향), normal(좌우), cumulative s(누적 거리) 계산
- z_ref가 없다면 terrain + safety margin으로 초기 권장 고도 생성
- z_ref가 있으면 그대로 사용하되, reward에서 “권장 고도”로만 쓰고 절대 강제는 하지 않는다.

5.4 corridor 정의
- ref path 중심선 기준 좌우 corridor를 생성
- 예:
  - hard corridor width: ±1000 m
  - soft corridor width: ±400 m
- hard corridor를 벗어나면 강한 페널티
- soft corridor를 벗어나면 완만한 페널티
- 위험이 큰 구간에서는 corridor width를 locally widen하는 옵션도 가능

5.5 Frenet 좌표계
- 현재 항공기 상태를 ref path에 투영하여 Frenet-like feature를 만든다.
- s: ref path를 따라 얼마나 진행했는가
- d: ref path에서 좌/우로 얼마나 벗어났는가
- heading_error: ref tangent와 현재 기수 방향 차이
- z_ref_error: 권장 ref 고도와의 차이
- 이 feature는 observation과 reward에 매우 중요하다.

================================================================================
6. DEM 전처리 및 지형 분석
================================================================================

6.1 전처리 목표
- GeoTIFF를 실시간 RL에 바로 쓰면 느리므로, 학습 전에 terrain feature와 risk layer를 전부 캐시한다.

6.2 기본 처리 단계
1) GeoTIFF 로드
2) 여러 타일이면 mosaic
3) metric 단위 투영 좌표계로 재투영
4) 시나리오 영역 crop
5) target resolution으로 resample
6) nodata 처리
7) feature 생성
8) risk map 생성
9) route profile 생성
10) cache 저장

6.3 권장 해상도
- 원본 보관: 가능한 한 원본 유지
- 학습용 base grid:
  - 20 m ~ 40 m 권장
- 초기 실용 구현은 30 m 권장
- local patch 추출은 base grid 또는 pyramid level 사용

6.4 지형 특징(feature) 목록
필수
- elevation
- relative_elevation (local mean 대비 상대 높이)
- slope
- aspect_sin, aspect_cos
- roughness (국지 표고 표준편차)
- local_relief (window 내 max-min)
- TPI (topographic position index)
- curvature (간략화 버전 가능)

권장 추가
- ridge_exposure_proxy
  - TPI가 높고 curvature가 볼록인 곳은 능선/노출 지형으로 간주
- valley_proxy
  - TPI가 낮고 주변 relief가 큰 곳
- clearance_margin_map
  - 특정 비행 고도 밴드 기준 여유
- landing_suitability_map
  - 평탄성, roughness, local relief로 만든 비상착륙 적합도

6.5 간단한 계산 예시
- slope = atan(sqrt((dz/dx)^2 + (dz/dy)^2))
- roughness = std(elevation, window=5x5 or 7x7)
- local_relief = max(window) - min(window)
- TPI = elevation - mean(neighborhood)
- ridge_exposure_proxy = sigmoid(a*TPI + b*positive_curvature + c*local_relief)
- landing_suitability = high when slope low, roughness low, relief low

================================================================================
7. 경로 주변(Route-Centric) 지형 분석
================================================================================

이 파트가 이번 요구사항에서 매우 중요하다.
단순히 “현재 지점 주변”만 보는 것이 아니라 “가야 할 ref 경로 주변”을 미리 분석해야 한다.

7.1 ref path 샘플링
- ref path를 50 m 또는 100 m 간격으로 샘플링
- 각 샘플마다 좌/우 normal 방향으로 corridor band를 만든다.

7.2 corridor band 설계
예시
- left band
- center band
- right band

예시 폭
- center band: ref path 중심 ±100 m
- left band: -500 ~ -100 m
- right band: +100 ~ +500 m

이렇게 하면 “앞으로 가야 할 길의 왼쪽/가운데/오른쪽 중 어느 쪽이 더 안전한지”를 요약할 수 있다.

7.3 각 샘플 지점에서 계산할 값
각 lookahead sample i에 대해 band별로 계산
- mean_elevation
- max_elevation
- mean_slope
- mean_roughness
- mean_risk
- p95_risk
- landing_suitability_max
- no_fly_fraction
- obstacle_density

7.4 route risk profile
- 결과를 K-step lookahead profile로 저장
- 예:
  corridor_profile[k, band, feature]
- 예를 들어 K=20, band=3, feature=6
- 이는 observation에 들어가며, agent가 “앞쪽 좌/우 중 어느 쪽이 나은지” 판단하는데 도움을 준다.

7.5 ref path 자체의 사전 보고서
학습 전/평가 전 미리 route report를 만든다.
- 구간별 평균 위험
- 구간별 최대 위험
- 최소 예상 AGL 여유
- 좌측 우회가 유리한 구간
- 우측 우회가 유리한 구간
- hold 필요 가능성이 큰 bottleneck 구간
이 보고서는 운영자와 개발자 모두에게 매우 유용하다.

================================================================================
8. 위험도(risk) 설계
================================================================================

8.1 risk 개념
- risk는 하나의 값으로 통합하되, 내부적으로는 여러 레이어의 합성으로 만든다.
- hard constraint와 soft cost를 분리하는 것이 좋다.

8.2 hard constraint 예시
- terrain collision
- map out of bounds
- hard no-fly zone 진입
- AGL < minimum_clearance_critical
- obstacle collision

8.3 soft risk 예시
- AGL 부족 경향
- slope/roughness/local_relief가 큰 곳
- ridge_exposure_proxy가 큰 곳
- populated area 상공
- temporary restricted area 근접
- weather risk
- landing suitability가 너무 낮은 구간
- ref path에서 너무 멀어짐

8.4 static risk map 예시
R_static =
  w1 * clearance_deficit_norm
+ w2 * slope_norm
+ w3 * roughness_norm
+ w4 * local_relief_norm
+ w5 * ridge_exposure_proxy
+ w6 * no_fly_soft
+ w7 * obstacle_proximity
+ w8 * population_risk
+ w9 * (1 - landing_suitability)

8.5 dynamic risk map 예시
R_dynamic =
  wd1 * weather_risk
+ wd2 * temporary_airspace_risk
+ wd3 * visibility_risk

8.6 최종 risk
R_total = clip(R_static + R_dynamic, 0, 1)

8.7 중요한 설계 포인트
- risk는 “절대적으로 지나가면 안 되는지”와 “가급적 피해야 하는지”를 구분해야 한다.
- 즉,
  - hard zone = terminate 또는 강한 penalty
  - soft zone = 우회하도록 유도

8.8 초기 권장 weight 방향
- clearance_deficit > no_fly > obstacle > slope/relief > population > landing
- 초기에는 clearance와 hard constraint를 가장 크게 둔다.
- 학습이 안정화되면 smoothness와 path adherence 비중을 높인다.

================================================================================
9. 시뮬레이션 상태와 운동학
================================================================================

9.1 상태(state)
world state
- x [m]
- y [m]
- z [m, AMSL 또는 local datum]
- v [m/s]
- psi [rad]
- vz [m/s]
- hold_mode [0/1]
- hold_timer [s]

derived state
- terrain_h = DEM(x, y)
- agl = z - terrain_h
- s = progress along ref path
- d = cross-track distance
- heading_error
- z_ref_error
- dist_to_goal
- local_risk
- risk_ahead
- route_band_preference

9.2 시간 간격
- dt = 1.0 s 권장
- 더 부드러운 제어가 필요하면 0.5 s 가능
- 첫 구현은 1.0 s가 관리하기 쉽다.

9.3 단순 운동학 모델
- x_{t+1} = x_t + v_t * cos(psi_t) * dt
- y_{t+1} = y_t + v_t * sin(psi_t) * dt
- z_{t+1} = z_t + vz_t * dt
- psi_{t+1} = psi_t + yaw_rate_cmd * dt
- v_{t+1} = clip(v_t + accel_cmd * dt, v_min, v_max)
- vz_{t+1} = clip(vz_cmd, vz_min, vz_max)

9.4 hold 동작
- hold_mode는 hovering 또는 very-low-speed loiter로 단순화
- 초기 구현 권장:
  - hold active면 target speed를 낮추고
  - 현재 지점 근처 반경 R_hold 안에서 머무르게 함
- 너무 복잡한 원형 선회 모델보다
  - “저속 유지 + 위치 drift 최소화” 단순화 모델이 초기에 더 실용적

9.5 권장 제한값(초기값)
- v_min = 0 ~ 5 m/s
- v_cruise = 40 ~ 55 m/s
- v_max = 70 m/s
- vz_min = -6 m/s
- vz_max = +6 m/s
- max_turn_rate = 10 ~ 15 deg/s
- agl_safe_min = 80 ~ 150 m (시나리오별 조정)
- agl_preferred = 120 ~ 250 m (시나리오별 조정)

주의
- 이 수치는 초기 시뮬레이션용 권장치이며 실제 비행체 성능자료에 맞춰 별도 조정해야 한다.

================================================================================
10. Action 설계
================================================================================

추천 기본안: continuous Box(4,)
a0 = yaw / heading change command
a1 = vertical speed command
a2 = speed command
a3 = hold command

10.1 action 해석
- a0 ∈ [-1, 1] -> yaw_rate_cmd ∈ [-max_turn_rate, +max_turn_rate]
- a1 ∈ [-1, 1] -> vz_cmd ∈ [vz_min, vz_max]
- a2 ∈ [-1, 1] -> accel_cmd 또는 target_speed_delta
- a3 ∈ [-1, 1]
  - a3 > +0.5 : hold 요청
  - a3 < -0.5 : hold 해제
  - 그 사이: 유지

10.2 왜 이 액션이 좋은가
- 사용자가 원한 “x,y,z,속도,holding” 요구와 잘 맞는다.
- ref path를 기준으로 하되 world frame으로도 자연스럽다.
- PPO/SAC/TQC에 바로 넣기 좋다.

10.3 대안(학습이 불안정할 때)
- Frenet action space
  - a0 = lateral offset target change
  - a1 = altitude target change
  - a2 = speed target change
  - a3 = hold
- 이 방식은 ref path가 고정된 경우 훨씬 쉽게 학습되기도 한다.
- 단, 물리적으로 world frame 해석이 조금 덜 직관적일 수 있다.
- 권장 순서:
  1) world-frame action 먼저
  2) 학습 불안정하면 Frenet action 실험

================================================================================
12. Reward 설계
================================================================================

12.1 reward 목표
- ref path 방향으로 진전해야 한다.
- 너무 멀리 이탈하면 안 된다.
- 위험한 곳은 피해야 한다.
- 지형과 너무 가까우면 안 된다.
- 고도/속도/기동이 불안정하면 안 된다.
- 필요 시 hold는 가능하되 남용하면 안 된다.

12.2 기본 reward 구조
r_t =
  + w_prog      * delta_s_progress
  + w_goal      * delta_goal_distance_reduction
  - w_d         * cross_track_error_norm
  - w_zref      * altitude_ref_error_norm
  - w_risk      * current_risk
  - w_risk_a    * risk_ahead_mean
  - w_clear     * clearance_deficit_penalty
  - w_smooth    * control_change_penalty
  - w_energy    * excessive_speed_or_climb_penalty
  - w_hold      * hold_time_penalty
  + w_hold_good * safe_hold_bonus_when_ahead_risk_high
  + terminal_bonus_or_penalty

12.3 중요한 보상 항목 설명
(1) delta_s_progress
- ref path 기준 진행량 증가 보상
- 단순히 goal과의 직선 거리 감소보다 더 안정적이다.

(2) cross_track_error_norm
- ref path에서 너무 멀어지는 것을 억제
- hard corridor 밖은 매우 강한 penalty

(3) current_risk / risk_ahead_mean
- 현재 위치와 앞으로 가야 할 corridor의 위험 평균
- 위험을 줄이는 방향으로 우회하도록 유도

(4) clearance_deficit_penalty
- agl이 안전 최소치보다 작으면 급격히 큰 penalty
- 예:
  relu(h_safe_min - agl) / h_safe_min

(5) control_change_penalty
- action jerk를 줄여 oscillation 억제

(6) hold 관련
- hold는 무조건 나쁜 것이 아니라,
  - 앞으로 risk가 높은데 무리하게 진입하는 것보다 잠깐 hold하는 것이 나을 수 있다.
- 따라서 “ahead risk가 높을 때의 짧은 hold”는 소량 보상 가능
- 그러나 장시간 hold는 penalty

12.4 terminal reward
- 성공:
  +100 ~ +300
- terrain collision:
  -100 ~ -300
- hard no-fly intrusion:
  -100 ~ -300
- out of bounds:
  -100
- timeout:
  -20 ~ -50

12.5 reward shaping 팁
- 초기에는 progress와 clearance를 크게 둔다.
- 학습이 안정되면 guide adherence와 smoothness를 높인다.
- risk 관련 weight는 지나치게 높이면 agent가 움직이지 않으려 할 수 있으므로 hold penalty와 균형 필요

15. stable-baselines3 기반 모델 설계
================================================================================

추천 실험 순서
1) PPO
2) RecurrentPPO
3) SAC
4) TQC

15.1 PPO
목적
- 가장 먼저 baseline으로 사용
장점
- 안정적
- 병렬 환경 구성 쉬움
- Dict observation + MultiInputPolicy 구조와 잘 맞음
권장 사용처
- dense reward 기반 초기 학습
- curriculum 초기 단계

15.2 RecurrentPPO
목적
- lookahead 정보가 충분치 않거나 partial observability가 남을 때 사용
장점
- 직전 상태 흐름을 기억
권장 사용처
- local patch만으로 앞 지형을 완전히 알 수 없을 때
- hold decision이 과거 맥락을 필요로 할 때

15.3 SAC
목적
- continuous control 정밀화
장점
- off-policy
- fine control에 강함
권장 사용처
- speed / climb / turn 연속 제어를 매끄럽게 다듬을 때

15.4 TQC
목적
- SAC보다 robust한 continuous control 대안
장점
- continuous action 문제에서 강력한 후보
권장 사용처
- SAC 성능이 흔들리거나 risk-sensitive tuning이 필요할 때

15.5 권장 우선순위
실전 순서
- PPO로 먼저 전체 파이프라인 완성
- 그 다음 RecurrentPPO로 성능 개선
- 이후 SAC/TQC로 미세 제어 향상

16. 네트워크 구조 권장안

16.1 feature extractor
- Dict observation을 받는 custom extractor 작성 권장

lookahead_ref branch

corridor_profile branch
- Flatten -> Linear(128) -> ReLU

fusion
- Concat -> Linear(512) -> ReLU -> Linear(256) -> ReLU

policy/value heads
- PPO:
  - pi head
  - vf head
- SAC/TQC:
  - actor head
  - critic heads

16.3 RecurrentPPO 구조
- 위 fusion feature 뒤에 LSTM(256) 추가
- policy/value head 분기

18. 기준 정책(heuristic baseline)

- reward sanity check
- env 디버깅
- RL 성능 비교 기준선

24. 구현시 주의점
================================================================================

- 처음부터 모든 레이어를 넣지 말 것
- DEM-only + ref path + clearance + cross-track reward부터 시작할 것
- heuristic baseline 없이 RL부터 돌리지 말 것
- reward를 너무 복잡하게 한 번에 넣지 말 것
- hold는 반드시 penalty와 함께 설계할 것
- ref path 주변 route profile은 매우 유용하므로 초기부터 넣는 것이 좋다
- world frame 상태와 ref path 기준 Frenet feature를 둘 다 유지할 것
- cache를 만들지 않으면 학습 속도가 매우 느려질 것
- 시뮬레이터는 학습용 렌더러가 아니라 분석용 도구로 설계할 것

26. 다른 AI에게 바로 줄 수 있는 구현 지시문
================================================================================

다음 조건으로 프로젝트를 구현하라.

1) 전역경로는 AI가 새로 생성하지 말고, 운용자가 사전에 넣은 ref path를 사용한다.
2) ref path는 거의 직선 위주의 polyline이며, RL은 이 경로를 기준으로 한 local 3D planner다.
3) 입력 DEM은 우선 resource/Hongik_48km.tif, resource/Inje_48km.tif, resource/Jipo_48km.tif 를 사용하고, 없으면 fallback SRTM tile들을 모자이크해서 사용한다.
4) DEM으로부터 elevation, slope, roughness, local relief, TPI, curvature, landing suitability, static risk를 계산하라.
5) ref path를 일정 간격으로 resample하고 Frenet feature(s, d, heading_error, z_ref_error)를 계산하라.
6) ref path 앞쪽 K-step corridor profile(left/center/right band)을 생성해 observation에 넣어라.
7) env는 x, y, z, v, psi, vz, hold_mode를 가지는 단순 운동학 모델로 만들고, action은 heading/climb/speed/hold continuous control로 설계하라.
8) observation은 Dict 형태로 state_vec, lookahead_ref, local_patch, corridor_profile을 포함하라.
9) reward는 progress, path adherence, risk minimization, clearance 유지, smoothness, hold 남용 방지를 모두 반영하라.
10) PPO baseline부터 만들고, 이후 RecurrentPPO, SAC, TQC로 확장하라.
11) FastAPI + HTML + Plotly 기반의 2D/3D 재생 시뮬레이터를 구현하라.
12) 코드 구조는 terrain/, route/, sim/, envs/, train/, webapp/ 등 기능별 폴더로 분리하라.
13) heuristic baseline(policy-based tracker, corridor shift, hold policy)도 같이 구현하라.
14) outputs/reports/ 아래에 route risk report와 episode metric report를 저장하라.
15) 처음에는 DEM-only로 시작하고, 이후 no-fly/obstacle/weather/population 레이어를 옵션으로 추가 가능하게 설계하라.
